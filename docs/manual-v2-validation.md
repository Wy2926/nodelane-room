# V2 人工及环境验收清单

执行时记录版本、架构、日期、结果及必要的脱敏证据。页面交互、真实安装及联网场景分别验收；HTTP/Go 测试不能替代它们。

## 页面：先准备一套隔离的 V2 控制端

| 场景 | 操作及预期 |
|---|---|
| 隐藏入口 | 根路径、旧 `/admin` 及其资源为 404 且无跳转；本机 `admin path` 获取入口，页面及资源可用；重启保留；配置新入口并重启后旧入口失效 |
| 初始化 | 单实例无业务环境变量启动，控制终端 bootstrap，10 分钟内填写数据库、公网地址、地址池、账号密码并生成或上传 CA；同一初始化码再次使用拒绝；过期码拒绝；成功后不能重新初始化 |
| 登录与退出 | 正确密码进入；错误密码给出反馈；频繁失败限流；退出后刷新/旧页面写操作不能成功 |
| 多实例接入 | 另行部署单实例并选择接入；错误管理员拒绝，成功后共享配置、CA、会话及事件；各实例重建保留状态 |
| 修改密码 | 系统页填写期间等待多个 5 秒 SSE 周期，输入不丢失；修改后所有标签页/另一副本会话失效；新密码可登录 |
| 多标签页 | 同时打开两个管理页，两者都能正常提交；不会因刷新另一个页面导致 CSRF 失效 |
| 创建与密钥 | 默认端口 4242、区域 default、两角色开启；非法入口拒绝；生成密钥只展示一次；关闭重开不能看到旧密钥；重生成旧码失效 |
| 部署指引 | curl 指向当前 HTTPS origin，非默认池带 network 参数；下载 YAML 填入控制 URL、端口和 0.2.0；文件不含密钥 |
| 离线配置 | 离线节点保存配置后显示等待接收；上线再显示应用中/已生效；失败显示原因，不提前成功 |
| UDP 端口 | 改端口先保持旧配置运行；修改本机/YAML 后执行对应 config apply；旧版本拒绝 |
| 生命周期 | 停止分配、恢复、停用、重启、替换和永久撤销均有明确说明；操作记录区看到最终结果及原因；离线时不误报完成 |
| 房间 | 建房、入房、登记端口后查看成员及端口；管理员踢人关闭已建连接并拒绝重入；关房后清理授权 |
| SSE | 网络断开显示重连；恢复后节点/房间/操作与完整快照一致；切换控制副本仍能操作 |
| 系统与 CA | 部署身份/地址池只读；显示 CA 到期日期；检查剩余 30/7/1 天提醒；无虚构 HTTPS 自动轮换承诺 |
| 桌面与窄屏 | 标签、表格、对话框、错误提示及退出可操作；键盘焦点可见，表单可用 Tab/Enter；长中文名称/IPv6入口不会盖住按钮 |
| 真实状态 | 未登记/失联/引擎停止分别显示；首节点无探测为尚未验证；UDP 阻断而 HTTPS 正常时不能显示公网 UDP 已验证；relay 路径不冒充直达 |
| 最近监控 | 连续传输至少 30 秒，节点/房间/成员连接、上传下载和趋势随实际数据变化；窗口为 60 秒，15 秒无上报显示过期；重启控制实例后历史清空，数据库无采样数据 |
| 路径与探测 | 分别建立 P2P 与中继，核对实际隧道及中继 IP；注入受控延迟/丢包，成员探测与房间最低/最高延迟变化；无探测显示未知，不能显示 0 |
| 出口与地区 | 比对节点/对端实际观察的成员 IP:端口及观察时间；不同 NAT 映射可展示多个出口；无手动下载时自动加载 DB-IP 核对国家/省州；更新失败保留旧库，首次未就绪或无记录显示未知 |
| 流量采集权限 | Linux 节点具有 CAP_NET_RAW 与 AF_PACKET 权限时中继转发产生双向流量；缺权限或采样丢失时显示未知；Windows 对照 Wintun 网卡计数，重启后速率不出现尖峰 |

## 原生安装：真实隔离虚拟机，不能用普通容器代替

分别覆盖 Debian 12/13、Ubuntu 22.04/24.04，amd64/arm64。先保存虚拟机快照，准备支持 TUN 的内核和不冲突网络。

1. 使用从控制端下载的脚本第一次安装。核对系统服务、专用用户、NET_ADMIN/NET_RAW、AF_PACKET、0700/0600 权限和全局 nlroom-node 命令。
2. 在装有 Docker 的宿主重复执行，仍只安装宿主服务；在容器终端执行脚本明确拒绝。
3. 登记中断网络、强制结束 CLI、在身份持久化后中断进程；重试保持同一身份并恢复已提交绑定。
4. 重复安装/重启主机后保持身份、配置和正常续签；换 --server 时拒绝覆盖。
5. 缺 TUN、权限不足、网段/路由冲突、磁盘不可写、错误校验和应在明确步骤报错；不得自动扩大设备、防火墙权限。
6. 使用受控的下一版本发布清单测试 update；新程序启动失败应恢复旧程序；确认回滚保留身份。V2 首发只提供 0.2.0 包，跨版本更新需额外测试产物。
7. 卸载默认保留配置/身份；重新安装可恢复。弃用节点在控制台撤销。

## 容器、跨机及公网

本地 Docker 集成结果见 [验证记录](validation.md)，仍需在实际目标服务器/1Panel 验证：端口映射、安全组、TUN、持久化目录、多个地域 DNS、真实公网 UDP、控制副本切换和机器替换。arm64 的交叉构建/仿真不能替代 ARM 真机。

至少两台服务器和两个不同 NAT 的客户端，检查直连/relay/替补、UDP 阻断、外部入口变更后的重新验证、长时间运行和真实丢包。禁止把 Docker 隔离网段当成真实 NAT 打洞验收。

## Windows 和 Minecraft

使用 V2 新身份在隔离的 Windows 测试机分别验证：安装用户 SID 绑定、SYSTEM 服务、DPAPI、ACL、其他普通用户拒绝访问、Wintun 签名与加载、安装/卸载/升级、睡眠和网卡变化恢复。

两台 Windows 使用原版 Minecraft Java 1.21.1 及其他 TCP/UDP 游戏，分别建房和加入，使用与服务端配置一致的监听端口验证虚拟 IP 连接、修改端口后旧连接停止、通用端口增删、踢人/关房断连，以及两个不同 NAT 的直连和中继。回显服务不能替代游戏本体验收；游戏内 LAN 搜索、广播/组播发现暂未实现，后续验收见 [游戏网络规划](game-network.md)。
