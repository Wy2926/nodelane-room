# 客户端更新

更新覆盖 Windows 完整 EXE 安装包和 Ubuntu/Debian 完整 deb，版本由 `model.ClientVersion` 统一到 GUI、服务、CLI 和更新助手。基础设施节点仍使用原有节点更新流程。首次安装带更新组件和可信根的客户端需要人工安装一次；旧客户端无法通过远程规则获得原本不存在的更新能力。

## 发布与信任

使用 [go-tuf/v2](https://github.com/theupdateframework/go-tuf) 验证 root、timestamp、snapshot、targets 的签名、到期时间及版本递增；使用 [AWS SDK for Go v2](https://github.com/aws/aws-sdk-go-v2) 对接 S3 协议。客户端内置初始 `root.json`，本机受保护缓存保存已信任的最高版本。下载源、管理台和数据库不能自行建立新的签名信任。安装前再次验证完整 TUF 元数据、平台、版本、文件大小和 SHA256；仅允许比当前版本高的目标，Linux 恢复仅使用此次事务中已验证的上一版；Windows 失败后重新运行完整安装包修复。

签名身份与 Nebula CA、设备身份和存储凭据分开。根私钥离线保存；发布机器只需要 targets、snapshot、timestamp 三把私钥。私钥目录不能进入仓库、镜像或发布包。Linux 下目录权限为 0700，文件为 0600；Windows 下需用管理员权限在 `%ProgramData%` 的直接子目录创建密钥，使用 DPAPI 和 ACL，不能跨机器直接复制加密后的文件。生产环境需另外准备离线备份、受控发布流程及 Windows Authenticode 代码签名；TUF 签名不替代操作系统发布者签名。

在离线或隔离发布环境初始化一次：

```sh
go run ./scripts/updates -mode init -keys /secure/nlroom-signing -out dist/update-repository
```

把生成的初始 `root.json` 作为公开信任文件固定保存。构建所有客户端程序时注入同一初始根：

```powershell
./scripts/build.ps1 -Components client -UpdateRoot ./dist/update-repository/root.json
```

Linux 开发构建通过 `NODELANE_UPDATE_ROOT=/secure/bootstrap-root.json sh scripts/build.sh` 注入。完整桌面包仍按 README 的打包流程构建。没有根的开发构建明确显示“未配置更新信任”，不会安装远程包。客户端更新完整包必须保留既有初始根或经过已发布轮换链的新根。

完整包构建及 Windows 发布者签名完成后签署文件，签署后禁止修改包：

```sh
go run ./scripts/updates -mode sign -keys /secure/nlroom-signing -out dist/update-repository -package dist/desktop/nlroom_0.3.0_amd64.deb -version 0.3.0 -os linux -arch amd64
go run ./scripts/updates -mode sign -keys /secure/nlroom-signing -out dist/update-repository -package dist/desktop/nlroom-0.3.0-windows-amd64-setup.exe -version 0.3.0 -os windows -arch amd64
```

每次签署保留已有 targets；相同文件名不可覆盖成不同内容。元数据默认有效七天，可用 `-days 1..30` 调整。到期前运行不带 `-package` 的 `-mode sign` 续签并导入管理台；过期后客户端拒绝安装。根默认一年有效，使用 `-mode rotate-root` 生成旧根和新根双签的下一版，导入包含完整轮换链的清单。保留所有已发布根；当前实现最多携带 64 次轮换，总元数据不超过 2 MiB。轮换后需验证从最早仍受支持客户端的初始根可以更新。签名工具输出的是文件，不会上传或发布。

## 控制面配置

控制面配置以下环境变量，所有连接同一数据库的实例保持一致：

- `NODELANE_UPDATE_ROOT`：管理员部署的初始公开根文件路径。容器中以只读文件挂载；也可以在构建控制程序时内置根。
- `NODELANE_UPDATE_STORAGE_KEY`：32 个随机字节的标准 Base64，用于 AES-GCM 加密数据库中的存储凭据。通过部署密钥管理注入，不填写到客户端。更换此密钥前需重新录入所有源的凭据；不能直接切换后继续读取旧密文。

管理台只管理对象存储连接信息，不接收签名私钥。凭据写入后不回显，不进入审计事件。部署模板的 `TMPDIR` 指向控制面可写状态卷，用于临时元数据和完整包上传；每个实例最多同时处理两项包上传/校验，需为两个最大安装包预留空间。异常退出可能留下 `nlroom-upload-*` 临时文件，停止对应控制实例后可清理。反代必须允许对应包大小及上传时长；API 最大安装包为 2 GiB，包接口最长读写窗口 40 分钟。使用带上传大小限制的 CDN 反代时，大文件先通过 S3 工具上传，再在管理台“验证源上已有包”。

新数据库结构为 6。仅初始化空库或打开当前结构；旧结构会报错，不迁移、不补表、不自动清空。无须保留旧业务数据时，部署新独立空库并重新配置 CA、用户及节点。

## 存储源与更新管理

管理台“更新管理”包含版本与发布、存储源、更新规则、设备版本四页。

| 源 | 配置 |
|---|---|
| Cloudflare R2 | Endpoint `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`、Bucket、Region `auto`、Access Key、Secret Key；凭据仅授予目标桶必要读写权限 |
| AWS S3 | 对应 Region 的 HTTPS Endpoint、Bucket、Region 和凭据 |
| MinIO / S3 兼容 | HTTPS Endpoint、Bucket、Region 和凭据，按部署开启 Path Style |
| HTTPS / CDN 镜像 | 公开 HTTPS 下载根地址和对象前缀；只验证已有文件，不向此源上传 |

每个源可以配置前缀、启停和优先级，最多 16 个。数字越小越优先，其余作为下载备用源。S3/R2 不设置公开地址时由控制面生成两小时有效的预签名 URL；设置公开地址后通过该地址下载及校验。公开根地址之后会追加对象前缀和已签名文件名。客户端不接收存储凭据。R2 公网分发使用自定义域名；[R2 S3 兼容接口](https://developers.cloudflare.com/r2/api/s3/api/)、[公开桶与自定义域名](https://developers.cloudflare.com/r2/buckets/public-buckets/)说明具体平台限制。

发布步骤：

1. 保存存储源并测试连接；该步骤仅验证连接，尚不证明包可用。
2. 导入签名工具生成的 `repository.json`。
3. 填写签名清单中的安装包文件名和更新说明，创建草稿。版本、平台、大小和摘要均取自签名元数据。
4. 为每个源上传完整包，或验证源上已有包。服务端完整下载并核对 SHA256 后才记录可用副本。
5. 发布版本，并为对应 OS/架构选择推荐版本；需要强制更新时另填最低允许版本和生效时间。

修改地址、Bucket、前缀、公开地址、寻址模式或凭据会使该源的旧验证失效，需重新验证。调整名称、优先级和启停保留字节校验记录。切换源时先验证备用源；仍被规则引用的版本必须至少保留一个启用且已验证的源。暂停/撤回版本前先移除或替换引用规则。客户端在下载后再次检查发布状态；已经开始的安装不会被管理台撤回中断。发布、规则、源配置有修订检查和审计，过期表单返回冲突。

Linux 自动更新要求服务端同时保留当前已安装版本的可信 deb，作为此次恢复包；它可处于已发布或已暂停状态。不要删除仍被设备使用的恢复包或其签名 target。缺少恢复包时客户端会停止安装并报告明确错误。

## 安装与恢复

服务每分钟检查更新，GUI 进入时主动检查并以暖白珊瑚色弹窗提示新版本。取消仅关闭本次版本提示；跳过此版本保存在当前用户的桌面偏好中，新版本仍会提示，强制更新到期后不允许跳过。点击立即更新后下载到受保护目录，支持断点续传、大小限制、镜像切换与最终摘要验证；普通 GUI 不直接执行下载链接或任意命令。磁盘预检为目标包大小的四倍加 256 MiB，安装前校验平台包身份。下载中显示实际接收字节、进度和采样速度，可取消请求；保留已下载部分供断点续传。下载和可信校验完成后 GUI 立即发起安装，无需再次确认；安装器启动后不提供强行中断。下载中可继续联机；安装前停止并等待网络服务。

Windows 用户点击安装并接受 UAC 后，由固定路径的 `nlroom-update.exe` 复制到受保护状态目录执行。NSIS 调用原生助手停止并等待后台退出、覆盖安装 GUI、服务与 CLI，保留原安装用户 SID，不执行 PowerShell，也不安装 TAP 或 WebView2；TAP 的启动检查见 [Windows 客户端](../README.md#windows-客户端)。健康检查要求新服务版本和本机 IPC 匹配。失败或中断后重新运行完整安装包修复，允许修复不完整的旧程序目录；不自动回滚、不保留上一版目录、不创建开机恢复任务。临时运行器只用于释放正在覆盖的更新助手，不在系统启动时执行。Windows 安装结束后用户重新打开客户端。下载完成不等于成功。

Linux 初次安装 deb 并绑定用户后，用户确认更新才下载，准备完成后由 GUI 启动独立 root `nlroom-update.service`。APT 只安装指定的可信 deb 及其依赖，禁止移除软件包，不进行系统全面升级；包管理器自行串行锁定。更新单元与网络服务分开，替换服务不会杀死自身。APT 已开始后等待其自然结束，避免超时杀进程留下并发 dpkg 子进程；可观察 `journalctl -u nlroom-update.service`。新服务未通过版本与 IPC 健康检查时尝试安装已验证的上一版。开机定时器处理未完成任务；底层包管理数据库损坏、依赖源故障或两版均启动失败需要管理员修复，并如实上报失败。

客户端身份、安装用户绑定和本机配置不随程序恢复回退。开发目录及不含完整安装器的包不执行系统更新。安装日志与客户端错误仅记录阶段及错误码，不记录密钥、会话、邀请码或预签名 URL。

## 强制规则与设备版本

规则按 Windows/Linux、amd64/arm64 独立配置。最低允许版本不能高于推荐版本；未设最低版本即普通推荐。截止时间到达后，服务端在创建、入房、续签和心跳的幂等响应之前检查版本，并通过清理任务撤销既有成员/证书授权和通知房间快照。客户端独立监测缓存截止时间并停止网络；离线不会延长现有授权。更新、诊断和账号退出仍可用。客户端自带检查为分钟级，已知截止时间本机检测间隔 250 ms；跨实例撤销通知受控制端清理周期及网络传播影响，不承诺所有设备同一毫秒断开。

设备在有账号身份时每分钟及结果变化时上报服务版本、GUI 版本、OS、架构、更新阶段、目标版本和错误码；不要求加入房间。管理台“用户 → 设备”显示版本和上报时间，“更新管理 → 设备版本”展示全库版本分布、分页设备列表和最近 100 条设备/版本结果。超过两分钟无报告标记陈旧，不把最后一次上报当成在线状态。结果按设备/版本保留最后阶段，进度字节仅保留本机，避免持续写入数据库。版本信息是已认证设备的自述，不是远程软件完整性证明；生效规则下从未报告版本的设备拒绝联机。

## 验证边界

自动测试覆盖签名篡改、过期、元数据回退、根轮换、断点续传和备用源、强制撤销及并发修订。发布前仍需在目标 Windows 与 Ubuntu/Debian 真机验证 UAC、驱动/服务、安装中断、重启、依赖故障和恢复，并使用实际 R2/S3/MinIO 配置验证上传、权限和公网镜像。具体本次运行结果见 [验证记录](validation.md#客户端更新验证)。
