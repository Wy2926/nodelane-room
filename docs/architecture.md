# 架构、协议与安全边界

按任务读取相关章节；字段与响应查 [OpenAPI](openapi.yaml)，帧授权和 MTU 查 [游戏网络](game-network.md)，操作查 README/部署指南，实际检查查验证记录。

## 代码组织

- 单 Go 模块、四个 Go 命令，另有独立 Tauri GUI。`cmd` 负责参数、命令、输入输出和进程装配，业务放内部包；命令增长时在入口包内按职责分文件。
- `agent` 协调玩家与节点，共用一套授权到期、Nebula 和探测生命周期；节点专属逻辑按文件隔离，保留既有锁边界。`control` 保持单包，HTTP 按调用方分文件，事务按领域组织，避免为跨包调用暴露内部授权操作。
- `localapi` 提供本机协议与客户端，`client` 提供控制面 HTTPS/SSE 客户端。CLI 和 `nodehost` 通过本机协议调用后台；控制面与 `agent` 不互相导入，平台存储不依赖 HTTP 客户端或业务运行时。
- `model` 仅放共享协议及基本校验，依赖标准库；`device` 放设备身份和持久化配置，仅依赖标准库及 `model`。数据库驱动仅在 `control` 使用；Nebula 运行时仅在 `engine` 使用，`agent`、`pki` 可使用 `nebula/cert`。
- `lan` 负责 TAP 生命周期、Ethernet 授权与分片，仅依赖 `model` 及平台开源组件；`engine` 用 Nebula 公开 DeviceFactory 接入，不将 Nebula 运行时扩散到其他包。
- 导入白名单以 [依赖检查](../scripts/architecture/boundaries_test.go) 为准，禁止内部包导入入口或构建脚本。检查扫描所有平台生产源码，测试可跨包构造客户端；随 CI 全量测试执行。文件职责和索引检查见 [索引](files.md#完整文件索引)。

## HTTP 与本机接口

`registerPlayer`、`registerNode`、`registerAdmin` 显式绑定具名处理函数，不按 URL 二次分派。共用调用方认证与幂等包装，保留限速、管理写失败审计及事务内会话复查；授权复查、状态修改、幂等和事件写入保持在同一业务事务。

| 调用方 | 接口 | 认证 |
|---|---|---|
| 玩家服务 | `/v2/auth/*`、`/v2/rooms/*`、`GET /v2/games` | player Bearer 会话 |
| 游戏图片 | `/v2/games/{game}/images/{image}` | 公开的已下载 JPEG/PNG，只读 |
| 实例初始化 | `/v2/admin/setup` | 同源 Origin、本实例 10 分钟初始化码；接入另验管理员密码 |
| 管理页面 | `/v2/admin/*` | 管理员 Cookie；写操作校验 Origin 和 CSRF |
| 基础设施节点 | `/v2/node/*` | 登记密钥与挑战；登记后使用 node Bearer 会话 |
| 浏览器与安装器 | `/{实例私有入口}`、其下 `/assets/*`、`/install/{file}` | 页面入口随机持久化或显式配置，资源按白名单；根路径与 `/admin` 为 404 |
| 运维探针 | `/healthz`、`/readyz`、`/metrics` | 反代限制指标外部访问 |

React 管理台构建后嵌入 Go。三类身份不能互换，房间操作只注册支持的动作。管理员在独立一致性快照中读取房间、成员和端口，不借用房主身份，不返回节点或撤销列表；玩家与节点使用各自授权的数据面快照。

本机 `/rpc` 经 Named Pipe/Unix socket 限制访问；节点健康与指标使用独立监听器，不属于公网控制 API。字段与响应以 [OpenAPI](openapi.yaml) 为准。

## 控制实例与配置

每套 Compose 默认一个控制服务。多个实例通过同一 PostgreSQL 数据库和 schema 组成同一控制面，各自拥有私有启动目录。初始化事务保存管理员、地址池、公网 origin、节点镜像仓库、数据库连接信息和 CA；接入已有部署须在事务内验证管理员密码及版本，不读取旧环境配置或 CA 文件。

实例启动只需受保护的本地数据库定位文件，原子发布阻止单个实例绑定不同数据库；共享状态正确性由数据库事务保证。CA 私钥仅在数据库及控制服务内存，不经页面、日志、事件或节点分发。目录权限、接入与恢复步骤见 [部署指南](deployment.md#本地持久化与备份)。

未配置时只提供初始化页面和存活探针，业务未就绪。读取完整数据库配置后一次性发布不可变服务；重启从同一数据库恢复，数据库失联不自动重新初始化。反代用 `/healthz` 保持初始化页面可达，业务检查用 `/readyz`。

## 本机权限

`nlroom-cli` 和已实现的 `nlroom` GUI 均以普通用户身份调用独立 `nlroom-service`，窗口关闭不结束后台。Windows 经 HTTP-over-Named-Pipe 请求 SYSTEM 服务；管道 DACL 只允许安装 SID、SYSTEM 和管理员。身份文件使用 machine DPAPI 及仅 SYSTEM/管理员可读的目录 DACL；DPAPI 不替代 ACL。Linux 安装用户 UID 与双向 socket 身份校验见 [桌面架构](client.md#桌面架构)。

设备 Ed25519 私钥持久保存，隧道 X25519 私钥在每次网络生命周期生成并仅保留在服务内存；GUI 不接触私钥或设备会话。

Windows 状态目录只能位于 ProgramData 的直接子目录，使用最终 ACL/管理员所有权原子创建；拒绝普通用户预创建的目录、重解析点和用户可控制的父目录。安装文件放在管理员拥有的 Program Files 目录。不能通过把状态移到用户可写路径来绕过服务权限错误。

## 事务与快照

共享业务写事务由 `Store.Write` 使用固定 PostgreSQL advisory lock 串行化；读快照可并发。此设计优先保证跨副本一致性，增加控制副本不会直接提升这条写路径的并发吞吐；锁粒度调整须以压测为依据，并保持授权、状态、幂等和事件的原子性。限速计数另用数据库原子 upsert。

设备认证通过 HTTPS 一次性挑战与 Ed25519 签名，设备 ID 为公钥 SHA-256 的小写十六进制；签名格式和编码见 OpenAPI。挑战一分钟、一次验证尝试；会话一小时，数据库仅存令牌哈希。邀请码和登记凭据也只存哈希；幂等缓存为恢复已执行操作暂存完整响应，属于敏感数据库内容。

玩家房间修改和节点领证 API 需要 `Idempotency-Key`，16–128 字符。幂等记录以设备与 key 为键，绑定路径及原始 JSON 字节，保留一小时。客户端对瞬时错误用同一 key 重试；重复不同请求返回 409。读取快照使用 PostgreSQL repeatable-read，房间 revision 单调递增，事件与状态在同一事务提交。

SSE 首先重放游标之后最多 256 个持久 `change` 通知，再发送完整 `snapshot`，然后每 5 秒发送一次权威快照。过老或过大的游标也获得当前快照。通知只是失效提示，消费者以完整快照为准，不能用通知载荷直接修改授权。流最长五分钟，然后客户端携带最近 revision 重连；服务端每轮检查会话。

## 数据面

固定 Nebula 完成基础设施 TUN、Noise 握手、证书校验、UDP 打洞、原生 relay 和 UDP 重绑定监控。生产启用 `punchy.punch`、`punchy.respond`；终端连接多个 lighthouse，NodeLane 更新静态入口和 relay 候选，无 relay 时仍可直连。强制中继限制仅用于回归，不进入生产。没有 TURN、WebRTC、HTTP 数据中继或公网 TCP 回退；完全封禁 UDP 的网络无法联机。

每份成员证书只有 `room:<id>` 组，基础设施只有 `infrastructure` 组。游戏统一使用 Ethernet LAN；外层默认拒绝，仅放行同房帧通道和必要诊断，内层再次校验成员与游戏规则。帧格式、MAC/IP 授权、端口、成员心跳有效期和 MTU 单处维护于 [游戏网络](game-network.md#授权与交付)。

叶证书最多十分钟，受房间/CA 截止时间约束。退出/踢人/关房在事务中撤销该范围证书和成员授权；快照携带仍有效的撤销指纹，Nebula blocklist 拒绝旧证书重握手，客户端主动关闭既有隧道并清理帧状态。撤销传播依赖控制连接，失联对端不能即时获知撤销；游戏帧仍受成员心跳和凭据截止时间限制，失联不延长授权。

客户端每 250ms 独立检查本机和对端证书截止时间，不等待可能卡住的 HTTPS 请求。系统时钟需同步，偏差超过 30 秒报告错误并暂停接受新配置；离线授权上界以本机可信时钟为前提。控制恢复后不会延用已到期的旧隧道密钥生命周期。

端口、LAN 策略或节点角色变化须 Stop/Wait 后重建数据面与探测，普通证书续签和撤销列表更新使用配置重载。固定版本的防火墙竞争、已授权握手补丁及剩余限制见 [补丁边界](nebula-race-review.md)；实际验收见验证记录。

## 游戏目录与网络规则

共享 `games` 保存资料、版本、启用状态与网络规则，`game_images` 保存校验后的 JPEG/PNG。Steam 导入在共享写事务外下载资料，成功后一次写入草稿、图片和审计事件；幂等重试不依赖外部网站恢复。固定来源、公开目标 IP 校验、重定向与大小限制避免任意地址代理。

游戏规则、成员绑定和心跳在同一 repeatable-read 事务快照中下发；同房活跃 MAC 受数据库唯一索引和共享写事务保护。配置修改与房间/管理事件同事务提交，普通心跳只更新时间。LAN 数据结构与能力契约见 [授权与交付](game-network.md#授权与交付)。

所有游戏（含 `custom`）由管理员配置，客户端只读；停用禁止新建/加入，旧房间撤回游戏流量授权，保留管理与必要诊断。游戏协议不分专用代码，无旧模式回退；操作见 [游戏管理](../README.md#游戏管理)。

## V2 管理与节点协议

管理员、玩家和节点会话完全分域。Ed25519 签名中的 scope 分别为 `player`、`node`、`enrollment`。管理员使用 Argon2id（64 MiB、3 次、并行度 1），会话 Cookie 为 Secure、HttpOnly、SameSite=Strict；数据库仅保存会话和 CSRF 的哈希。会话有效期 12 小时、空闲上限 30 分钟。修改/重置密码删除全部会话，管理写请求在事务中复查会话并验证 Origin/CSRF。登录和初始化共用速率限制。

逻辑节点 `nodes.id` 与机器 Ed25519 身份 `node_bindings.device_id` 分离。替换服务器增加 generation，撤销旧绑定、旧会话及证书，并隔离旧地址至少 11 分钟或至已签证书截止时间。永久撤销不可恢复。停用保留管理连接并停止领证；停止分配保留身份与续签，只从新连接候选移除。

登记前由管理员创建逻辑节点并签发 32 字节随机临时密钥，绑定节点、generation 和配置 revision；有效 30 分钟。控制端先验证密钥再创建一分钟挑战。节点先原子持久化身份，签署挑战，控制事务内消费密钥、绑定身份、分配地址并写事件。响应或本地保存中断后，节点用已保存身份走 `/v2/node/auth/*` 和 sync 恢复，不要求再次消费密钥。旧身份不能作为新玩家身份重新注册。

接入密钥明文仅在签发响应返回；不进入审计、日志、数据库或幂等缓存。重新签发或修改待登记配置撤销旧未用密钥。没有公开申请、网页配对码或 V1 登记路由。

节点约每 5 秒 POST sync，报告版本、引擎、证书截止时间、已应用配置和探测结果。期望配置历史保留；报告的已应用配置须与历史版本完全相符。客户端发现使用节点已确认的公网入口/角色，避免未应用的新端口提前影响连接。端口变更需要本机明确 apply；容器还需先更新端口映射及声明并重建。角色/端口/游戏规则变化 Stop/Wait 后重启；普通证书续签通过配置重载完成。

节点操作带 ID、绑定代次、配置版本和 24 小时有效期。本机执行前保存检查点，确认后上报；数据库幂等记录终态，拒绝旧代次。控制面只在确认应用后显示成功。离线节点保留待执行状态，过期操作不执行。

管理 SSE 每 5 秒发送完整当前快照，id 为持久管理事件游标。任意 Last-Event-ID 都能恢复当前状态；快照附最近 200 条审计、200 条操作和 500 个最近房间（节点不截断）。流最长 5 分钟并每轮验证会话；它与房间 SSE 的 change 重放协议不同。系统信息展示部署身份、只读地址池和 CA 到期日，剩余 30/7/1 天均在页面提醒范围内。

公网连通证据来自另一已登记节点的 Nebula 路径与探测回复，记录来源、目标入口、远端地址和时间。只有 direct 路径且远端 IP/端口与登记域名当前解析相符才显示公网 UDP 已验证；relay 成功仅证明隧道可达。最新探测失败不以历史平均 RTT 冒充成功。首次部署没有外部观察者时显示尚未验证，不阻止首个节点启动。

## 监控

节点和玩家每 5 秒分别向 `/v2/node/telemetry`、`/v2/rooms/{room}/telemetry` 上报，管理台每 5 秒读取 `/v2/admin/telemetry`。控制实例只保留最近 60 秒有界内存样本，15 秒无更新视为陈旧；重启清空，多实例不合并，不写入 PostgreSQL、审计、幂等或 SSE 事件。认证及对端身份/IP 归属校验使用 PostgreSQL 当前授权，采样不参与授权、地址分配或撤销决策。

路径和远端地址只查询固定 Nebula hostmap，RTT/丢包来自最近 60 秒实际探测。成员字节来自 Windows IP Helper / Linux TAP 网卡计数；内部探测不经过 TAP，游戏与内部探测统计口径分开；计数重置或采样断档不推算速率。房间连接按成员对去重，不含基础设施隧道；流量为成员接口之和，发送计上传、接收计下载，另显示上报覆盖人数。

Linux 节点用 AF_PACKET 和内核 BPF 过滤本机 Nebula UDP 端口，最多读取 68 字节包头，统计握手、诊断及中继转发的 UDP 负载字节。观察器不参与收发决策、不保存报文；缺少权限或采集丢包时流量返回未知。节点展示实际隧道数、速率、窗口流量和逐对端链路。

出口必须来自真实观察，附观察方；NAT 对不同目标可使用不同端口，不能用 HTTP 来源、配置入口、中继地址或历史结果冒充当前出口。GeoIP 只查询本地 MMDB，不向第三方发送成员 IP；采集权限与 GeoIP 配置见 [部署指南](deployment.md#监控与-ip-归属地)。

单次最多上报 128 个对端，超出时轮转，总连接数仍来自完整 hostmap。每实例最多接纳 1024 个上报身份，内存按保守估计限制为 64 MiB，满载返回 429，不挤掉已接收窗口。
