# 协议与安全边界

## 代码与接口边界

`internal/control` 保持单个 Go 包：HTTP 按调用方分文件，事务逻辑按房间、节点、身份及存储职责组织，避免为跨包调用暴露内部授权操作。目录入口见 [文件索引](files.md)。

各调用方在 `registerPlayer`、`registerNode`、`registerAdmin` 中显式绑定路由与具名处理函数；处理函数不再按 URL 二次分发。玩家和管理员共用各自的认证与幂等包装，各接口保留原有限速，管理员写操作保留失败审计和事务内会话复查。房间操作、管理会话、节点管理与事件流按职责分文件；新增接口同步对应处理函数、测试和 OpenAPI。

| 调用方 | 接口 | 实现 | 认证 |
|---|---|---|---|
| 玩家 CLI/服务 | `/v2/auth/*`、`/v2/rooms/*` | `player_http.go`、`player_rooms_http.go`、`player_events_http.go` | player Bearer 会话 |
| 管理页面 | `/v2/admin/*` | `admin_http.go` 注册，`admin_{session,nodes,rooms,events}_http.go` 处理 | 管理员 Cookie；写操作校验 Origin 和 CSRF |
| 基础设施节点 | `/v2/node/*` | `node_http.go` | 登记密钥与挑战；登记后使用 node Bearer 会话 |
| 浏览器与安装器 | `/admin`、`/admin/assets/{app.js,style.css}`、`/install/{file}` | `admin_web.go`、`install_http.go` | 公开页面与允许下载的文件 |
| 运维探针 | `/healthz`、`/readyz`、`/metrics` | `http.go` | 指标由反代限制外部访问 |

管理页面资源单独放在 `internal/control/adminweb/`，玩家入口为 `cmd/nodelane/`。三类身份不能互换；房间操作只注册支持的动作。管理房间详情在独立一致性快照中读取房间、成员和端口，不借用房主身份，不返回节点或撤销列表。玩家与节点仍使用各自授权的数据面快照。

本机 `/rpc` 由 `internal/agent/local.go` 承载，经 Named Pipe/Unix socket 限制访问；`node_local.go` 分派节点命令。节点存活、就绪和指标由 `health.go` 在独立监听器提供，不属于公网控制 API。完整契约见 [OpenAPI](openapi.yaml)。

## 分工

`nodelane` 的普通用户命令经本机 HTTP-over-Named-Pipe 请求 SYSTEM 服务。管道 DACL 只允许安装时指定 SID、SYSTEM 和管理员。服务写入的身份文件使用 machine DPAPI，加上仅 SYSTEM/管理员可读的目录 DACL；machine DPAPI 本身不替代 ACL。身份 Ed25519 私钥持久保存，隧道 X25519 私钥在每次网络生命周期生成并仅保留在服务内存。

Windows 状态目录只能位于 ProgramData 的直接子目录，使用最终 ACL/管理员所有权原子创建；拒绝普通用户预创建的目录、重解析点和用户可控制的父目录。安装文件放在管理员拥有的 Program Files 目录。不能通过把状态移到用户可写路径来绕过服务权限错误。

控制面通过 HTTPS 返回一次性挑战，设备签名 `UTF8("nodelane-auth-v2:" + scope + ":" + challenge_id + ":") || nonce`。设备 ID 为 Ed25519 公钥 SHA-256 的小写十六进制；JSON 字节字段是标准 base64。挑战一分钟、一次验证尝试；会话一小时，数据库只存令牌哈希。邀请码和登记凭据也只存哈希，幂等响应缓存为恢复已执行操作暂存完整响应，属于敏感数据库内容。

玩家房间修改和节点领证 API 需要 `Idempotency-Key`，16–128 字符。幂等记录以设备与 key 为键，绑定路径及原始 JSON 字节，保留一小时。客户端对瞬时错误用同一 key 重试；重复不同请求返回 409。读取快照使用 PostgreSQL repeatable-read，房间 revision 单调递增，事件与状态在同一事务提交。

SSE 首先重放游标之后最多 256 个持久 `change` 通知，再发送完整 `snapshot`，然后每 5 秒发送一次权威快照。过老或过大的游标也获得当前快照。通知只是失效提示，消费者以完整快照为准，不能用通知载荷直接修改授权。流最长五分钟，然后客户端携带最近 revision 重连；服务端每轮检查会话。

## 数据面

官方 Nebula 完成 TUN、Noise 握手、证书校验、UDP 打洞和原生 relay。终端连接多个 lighthouse；NodeLane 更新静态入口和 relay 候选。外层 UDP 重绑定使用 Nebula 自带网络变化监控。没有 TURN、WebRTC、HTTP 数据中继或公网 TCP 回退；完全封禁 UDP 的网络无法联机。

每份成员证书只有 `room:<id>` 组，基础设施只有 `infrastructure` 组。默认拒绝所有未列明端口；同房只允许 ICMP、UDP 4243 探测/发现及已登记端口。终端入站只开放自己登记的端口。房间跨组默认拒绝；发现消息另按快照验证房间、成员虚拟 IP、端点 ID、端口与有效期。

每个叶证书最多十分钟，并受房间/CA 截止时间约束。退出/踢人/关房在事务中撤销该范围所有证书、删除端点和成员授权；客户端与节点快照带仍有效的撤销指纹，Nebula blocklist 拒绝旧证书重新握手，封装主动关闭已有隧道。本机代理同时关闭已建立的 TCP 连接。撤销传播依赖控制连接；失联对端不可能即时得知撤销，因此安全上界是当前证书剩余有效期。

客户端每 250ms 独立检查本机和对端证书截止时间，不等待可能卡住的 HTTPS 请求。系统时钟需同步，偏差超过 30 秒报告错误并暂停接受新配置；离线授权上界以本机可信时钟为前提。控制恢复后不会延用已到期的旧隧道密钥生命周期。

固定 Nebula 版本的防火墙热更新发生数据竞争，因此修改端口规则时 Stop/Wait 后重新启动数据面并重建适配器；证书/撤销列表更新仍调用上游配置重载。握手缓存竞争使用经授权的 Wy2926/nebula 补丁提交修复，`go.mod` 保留上游模块路径并固定替换版本。补丁只调整握手完成与日志的顺序，不改变协议和权限；剩余上游限制与真机验收见验收记录，当前 V2 尚需完成环境验收。

## Minecraft 发现

监听 `224.0.2.60:4445`，只接受源 IP 属于本机的合法 `[MOTD]…[/MOTD][AD]port[/AD]`。端口经过本机 TCP 连接校验后登记，端点租期 45 秒、后台约每 10 秒刷新。控制服务不扫描玩家端口；适配器的本机检测不是对恶意本机管理员的防线。

发送端经 Nebula UDP 4243 单播发送 `{v:1,type:"advertisement",room,endpoint}`，不广播原始外部 IP。接收端查控制快照，将唯一端点映射到本机 TCP 代理。代理绑定用于组播回环的本机 IPv4，并且拒绝源 IP 不属于本机的连接；TTL 0 组播发布该代理端口，使 Java 客户端能使用广告源地址连接。代理不是 LAN 网关。

消息不超过 1024 字节，探测/广告按来源限速，端点最多 32 个、代理连接受限。通过端点 ID 区分同名世界，抑制自己发布的代理广告和重复通知，通知超时 8 秒或端点到期后关闭代理。多网卡加入各活跃接口组播组，发射接口采用操作系统的组播路由选择。NIC 改变、Windows Java 多播选择和睡眠恢复需按真机验收矩阵测试。

`game.Adapter` 提供 `Observations/Update/Notice/Events/Close`，有界发现事件可供后续 UI 消费；权威授权仍来自快照。游戏数据不经过控制面；转让房间管理权不会搬迁 Minecraft 存档或游戏进程。

## V2 管理与节点协议

管理员、玩家和节点会话完全分域。Ed25519 签名中的 scope 分别为 `player`、`node`、`enrollment`。管理员使用 Argon2id（64 MiB、3 次、并行度 1），会话 Cookie 为 Secure、HttpOnly、SameSite=Strict；数据库仅保存会话和 CSRF 的哈希。会话有效期 12 小时、空闲上限 30 分钟。修改/重置密码删除全部会话，管理写请求在事务中复查会话并验证 Origin/CSRF。登录和初始化共用速率限制。

逻辑节点 `nodes.id` 与机器 Ed25519 身份 `node_bindings.device_id` 分离。替换服务器增加 generation，撤销旧绑定、旧会话及证书，并隔离旧地址至少 11 分钟或至已签证书截止时间。永久撤销不可恢复。停用保留管理连接并停止领证；停止分配保留身份与续签，只从新连接候选移除。

登记前由管理员创建逻辑节点并签发 32 字节随机临时密钥，绑定节点、generation 和配置 revision；有效 30 分钟。控制端先验证密钥再创建一分钟挑战。节点先原子持久化身份，签署挑战，控制事务内消费密钥、绑定身份、分配地址并写事件。响应或本地保存中断后，节点用已保存身份走 `/v2/node/auth/*` 和 sync 恢复，不要求再次消费密钥。旧身份不能作为新玩家身份重新注册。

接入密钥明文仅在签发响应返回；不进入审计、日志、数据库或幂等缓存。重新签发或修改待登记配置撤销旧未用密钥。没有公开申请、网页配对码或 V1 登记路由。

节点约每 5 秒 POST sync，报告版本、引擎、证书截止时间、已应用配置和探测结果。期望配置历史保留；报告的已应用配置须与历史版本完全相符。客户端发现使用节点已确认的公网入口/角色，避免未应用的新端口提前影响连接。端口变更需要本机明确 apply；容器还需先更新端口映射及声明并重建。角色/端口/游戏规则变化 Stop/Wait 后重启；普通证书续签通过配置重载完成。

节点操作带 ID、绑定代次、配置版本和 24 小时有效期。本机执行前保存检查点，确认后上报；数据库幂等记录终态，拒绝旧代次。控制面只在确认应用后显示成功。离线节点保留待执行状态，过期操作不执行。

管理 SSE 每 5 秒发送完整当前快照，id 为持久管理事件游标。任意 Last-Event-ID 都能恢复当前状态；快照附最近 200 条审计、200 条操作和 500 个最近房间（节点不截断）。流最长 5 分钟并每轮验证会话；它与房间 SSE 的 change 重放协议不同。系统信息展示部署身份、只读地址池和 CA 到期日，剩余 30/7/1 天均在页面提醒范围内。

公网连通证据来自另一已登记节点的 Nebula 路径与探测回复，记录来源、目标入口、远端地址和时间。只有 direct 路径且远端 IP/端口与登记域名当前解析相符才显示公网 UDP 已验证；relay 成功仅证明隧道可达。最新探测失败不以历史平均 RTT 冒充成功。首次部署没有外部观察者时显示尚未验证，不阻止首个节点启动。
